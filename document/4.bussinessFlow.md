# 02. Business Logic

---

# Overview

This document defines the core business rules and workflows that govern the Sagau marketplace.

Unlike UI or API documentation, business logic describes **what the system must allow, prevent, and automate** to ensure a secure and trustworthy marketplace.

All backend services, controllers, and database operations should follow these rules.

---

# 1. Marketplace Lifecycle

The Sagau marketplace revolves around the complete hiring process.

```text
Client Registers
        │
        ▼
Creates Client Profile
        │
        ▼
Posts Job
        │
        ▼
Workers Discover Job
        │
        ▼
Workers Apply
        │
        ▼
Client Reviews Applications
        │
        ▼
Client Sends Offer
        │
        ▼
Worker Accepts Offer
        │
        ▼
Agreement Created
        │
        ▼
Work Starts
        │
        ▼
Worker Marks Work Completed
        │
        ▼
Client Reviews Submission
        │
        ▼
Agreement Completed
        │
        ▼
Both Users Review Each Other
        │
        ▼
Trust Score Updated
```

---

# 2. User Registration Rules

## Every User

Must provide:

- Full Name
- Email Address
- Password
- Selected Role

---

## Email Rules

- Must be unique.
- Stored in lowercase.
- Verified in future releases.

---

## Password Rules

Must:

- Be hashed before storage.
- Never be returned through any API.
- Never be logged.

---

## Roles

Allowed roles:

- Client
- Worker
- Admin

A user may only have one active role.

---

# 3. Profile Rules

## Client Profile

A client profile stores hiring-related information.

Includes:

- Contact Information
- Profile Photo
- Company Information (optional)
- Hiring History

---

## Worker Profile

A worker profile stores professional information.

Includes:

- Skills
- Experience
- Portfolio
- Bio
- Certifications
- Availability
- Verification Status
- Trust Score

---

## Profile Completion

Workers should gradually complete their profile.

Suggested completion criteria:

| Section         | Weight |
| --------------- | ------ |
| Profile Picture | 10%    |
| Bio             | 10%    |
| Skills          | 20%    |
| Experience      | 20%    |
| Portfolio       | 20%    |
| Verification    | 20%    |

Profile completion affects visibility in search results.

---

# 4. Job Posting Rules

Only Clients can create jobs.

Each job must contain:

- Title
- Description
- Budget
- Category
- Required Skills
- Location
- Deadline

---

## Job Status

```text
OPEN
    │
    ▼
ASSIGNED
    │
    ▼
IN_PROGRESS
    │
    ▼
COMPLETED

or

OPEN
    │
    ▼
CANCELLED
```

---

## Business Rules

Clients may:

- Edit OPEN jobs.
- Delete OPEN jobs.
- Close OPEN jobs.

Clients cannot edit a job after a worker has accepted the offer.

---

# 5. Job Discovery Rules

Workers can:

- Browse all open jobs.
- Search jobs.
- Filter jobs.
- Save jobs (future).

Jobs should be ranked by:

- Relevance
- Posting date
- Client rating
- Trust level
- Distance (future)

---

# 6. Application Rules

Only workers can apply.

Each application contains:

- Proposal
- Estimated Cost
- Estimated Duration

---

## Rules

A worker:

✅ Can apply once per job.

❌ Cannot apply to their own job.

❌ Cannot apply after the application deadline.

❌ Cannot apply if the job is already assigned.

---

## Application Status

```text
PENDING

↓

REVIEWED

↓

SHORTLISTED

↓

ACCEPTED

or

↓

REJECTED
```

---

# 7. Hiring Rules

Clients review submitted applications.

They may:

- View worker profiles.
- Compare ratings.
- Compare trust score.
- Compare portfolios.
- Compare verification status.

---

## Offer Process

Instead of immediately hiring:

```text
Application Selected
        │
        ▼
Offer Sent
        │
        ▼
Worker Accepts
        │
        ▼
Agreement Created
```

If the worker rejects the offer:

```text
Offer Rejected

↓

Client Selects Another Worker
```

---

# 8. Agreement Rules

Every accepted offer automatically creates an agreement.

The agreement connects:

- Client
- Worker
- Job

---

## Agreement Status

```text
DRAFT

↓

ACTIVE

↓

COMPLETED

or

↓

CANCELLED
```

---

## Agreement Includes

- Timeline
- Deliverables
- Payment Terms
- Responsibilities
- Conditions

---

# 9. Work Completion Rules

Worker finishes work.

↓

Worker submits completion.

↓

Client reviews submission.

↓

Client approves.

↓

Agreement becomes COMPLETED.

Only after completion can reviews be submitted.

---

# 10. Review Rules

Reviews can only be submitted for completed agreements.

Each agreement allows:

- One review from Client.
- One review from Worker.

---

## Review Components

### Rating

1–5 Stars

### Categories

Client → Worker

- Communication
- Professionalism
- Quality
- Timeliness

Worker → Client

- Communication
- Cooperation
- Payment Reliability

---

## Restrictions

A user cannot:

- Review twice.
- Review unrelated agreements.
- Edit reviews after submission (unless future moderation allows it).

---

# 11. Trust Score Rules

Trust Score is calculated automatically.

Suggested formula:

| Factor          | Weight |
| --------------- | ------ |
| Average Rating  | 40%    |
| Completion Rate | 25%    |
| Verification    | 20%    |
| Response Rate   | 15%    |

---

Trust Score updates after:

- Job completion.
- Review submission.
- Verification approval.
- Account activity.

---

# 12. Verification Rules

Workers may submit:

- Citizenship
- Passport
- National ID
- Certificates
- Licenses

Status:

```text
PENDING

↓

APPROVED

or

↓

REJECTED
```

Approved workers receive a verification badge.

---

# 13. Notification Rules

The system automatically creates notifications for:

- Job Application Received
- Offer Sent
- Offer Accepted
- Offer Rejected
- Agreement Created
- Agreement Updated
- Work Completed
- Review Received
- Verification Approved
- Verification Rejected

---

# 14. Admin Rules

Admins may:

- Suspend users.
- Ban users.
- Approve verification.
- Remove fraudulent jobs.
- Resolve disputes.
- Review reports.
- Monitor analytics.

Admins cannot participate in marketplace transactions.

---

# 15. Security Rules

Every protected endpoint must verify:

- Authentication
- Authorization
- Account Status

Blocked users cannot:

- Login
- Apply
- Post jobs
- Update profiles

---

# 16. Business Constraints

## One Application Per Worker

A worker may submit only one application for a specific job.

---

## One Agreement Per Job

Each job may have only one active agreement.

---

## One Accepted Worker

Only one worker can be hired for a job.

---

## One Review Per User

Each participant may submit only one review for a completed agreement.

---

# 17. Audit Trail

The system should log important events.

Examples:

- User Registered
- Job Created
- Application Submitted
- Offer Sent
- Offer Accepted
- Agreement Created
- Agreement Completed
- Review Submitted
- Verification Approved

Audit logs help with debugging, moderation, and dispute resolution.

# Conclusion

The business logic defined in this document represents the operational rules of the Sagau marketplace. Every backend controller, service, middleware, and API endpoint should enforce these rules to maintain consistency, trust, and platform integrity.

By separating business logic from implementation details, Sagau remains scalable, maintainable, and ready for future expansion.
