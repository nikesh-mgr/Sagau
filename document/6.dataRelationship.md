# 6. Data Relationship Model

---

# Overview

The Sagau platform uses a relationship-based data model that connects users, jobs, applications, agreements, reviews, and verification records into a unified marketplace ecosystem.

The data model is designed to support:

- Authentication
- Job Marketplace Operations
- Hiring Workflow
- Agreement Management
- Reputation Building
- Trust and Verification Systems

---

# 1. USER (Master Entity)

## Purpose

The User entity acts as the foundation of the entire system.

Every person who registers on the platform first becomes a User.

All authentication and authorization processes originate from this entity.

---

## Responsibilities

### Authentication

- Registration
- Login
- Logout
- Password Management

### Identity Management

- Name
- Email
- Profile Image
- Account Status

### Authorization

- Client Role
- Worker Role
- Admin Role

---

## Relationships

### One User → One Client Profile

```text id="pxq8m8"
USER 1 → 1 CLIENT
```

---

### One User → One Worker Profile

```text id="xw5mca"
USER 1 → 1 WORKER
```

---

### One User → Many Notifications

```text id="50zjlwm"
USER 1 → N NOTIFICATIONS
```

---

# 2. CLIENT PROFILE

## Purpose

Represents users who hire workers and create jobs.

A client profile stores hiring-related information separately from authentication data.

---

## Responsibilities

- Job Creation
- Hiring Management
- Agreement Participation
- Review Submission

---

## Relationships

### Client Creates Jobs

```text id="svf8j0"
CLIENT 1 → N JOBS
```

One client can create multiple jobs.

Each job belongs to exactly one client.

---

### Client Participates in Agreements

```text id="0h1vst"
CLIENT 1 → N AGREEMENTS
```

---

### Client Writes Reviews

```text id="m6lndh"
CLIENT 1 → N REVIEWS
```

---

Jobs are the central marketplace objects.

---

## Responsibilities

- Application Collection
- Lifecycle Tracking
- Hiring Workflow

---

```text id="xlbgtt"
 ↓
ASSIGNED
 ↓
IN_PROGRESS
 ↓
COMPLETED
```

```text id="0gx2oz"

```

# 5. APPLICATION

## Purpose

Application acts as a bridge entity between workers and jobs.

It records worker interest in a specific job.

---

## Relationship Type

```text id="q3y1nq"
WORKER ↔ JOB
```

This creates a many-to-many relationship.

Applications resolve that relationship.

---

## Responsibilities

### Proposal Storage

Stores:

- Proposal Message
- Estimated Cost
- Estimated Duration

---

### Application Tracking

Tracks:

- Pending
- Reviewed
- Accepted
- Rejected

---

### Duplicate Prevention

Ensures:

```text id="89ps5m"
One Worker
Can Apply
Only Once
Per Job
```

---

## Relationships

```text id="v2sknl"
WORKER 1 → N APPLICATIONS

JOB 1 → N APPLICATIONS
```

---

```text id="70j8vl"
WORKER
```

- Status Tracking

```text id="h3jdn8"
ACTIVE
 ↓
COMPLETED
```

## Relationships

# 7. REVIEW

## Purpose

Reviews form the reputation foundation of the platform.

Reviews are only allowed after successful completion of an agreement.

---

## Responsibilities

- Trust Building
- Reputation Tracking
- Ranking Calculation
- Quality Assessment

---

## Review Components

### Rating

```text id="utpjhm"
1 → Poor
2 → Fair
3 → Good
4 → Very Good
5 → Excellent
```

### Feedback

Written comments regarding:

- Communication
- Professionalism
- Work Quality
- Timeliness

---

## Relationships

### Review Linked to Agreement

```text id="wj68kr"
AGREEMENT 1 → N REVIEWS
```

---

### Review Author

```text id="gdrqfs"
CLIENT → REVIEW
WORKER → REVIEW
```

---

### Review Target

```text id="pw9k6q"
REVIEW → WORKER
REVIEW → CLIENT
```

---

# 8. VERIFICATION

## Purpose

Provides identity and skill validation.

Used to improve trust within the marketplace.

---

## Verification Types

### Identity Verification

- Citizenship
- Passport
- National ID

### Skill Verification

- Certificates
- Licenses
- Professional Documents

---

## Relationships

```text id="5kmlt0"
WORKER 1 → N VERIFICATIONS
```

---

# 9. NOTIFICATION

## Purpose

Provides real-time platform updates.

---

## Examples

- New Application
- Worker Selected
- Agreement Created
- Verification Approved
- Review Received

---

## Relationships

```text id="wf40ej"

```

# Overall Relationship Summary

| Entity       | Relationships                                   |
| ------------ | ----------------------------------------------- |
| User         | Client, Worker, Notifications                   |
| Client       | Jobs, Agreements, Reviews                       |
| Worker       | Applications, Agreements, Reviews, Verification |
| Job          | Client, Applications, Agreement                 |
| Application  | Worker ↔ Job                                    |
| Agreement    | Client ↔ Worker ↔ Job                           |
| Review       | Agreement, Reviewer, Target                     |
| Verification | Worker                                          |
| Notification | User                                            |
